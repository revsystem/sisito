## 決定事項

- PR #27 には `Gemfile.lock` の最小修正のみを含める。`CLAUDE.md` の追記は同じコミットや PR には含めない。
- ローカルではこのアプリの動作確認・Railsテストを行わない。必要ならリモートサーバーまたは CI で確認する。
- ローカル Ruby 環境を汚さない。必要な Ruby 操作が避けられない場合は rbenv を使う。
- pi の `~/sisito` への反映は、PR #24 を先にマージしてから判断する。

## 捨てた選択肢と理由

- PR #27 に `CLAUDE.md` 追記を含める案: ユーザーが「未コミットのCLAUDE.mdはこのコミットには含めない」と指示したため不採用。`CLAUDE.md` は未コミットのまま残した。
- pi の `~/sisito` に PR #27 の差分を強制適用する案: pi 側の `Gemfile.lock` には既に広範な bundle update があり、今回の修正バージョンも含まれていた。上書きすると先行作業を壊す可能性があるため不採用。
- pi で sisito を起動または再起動する案: 現在 sisito の ruby/puma プロセスがなく、`:3000` は Grafana だった。起動方法・ポート・運用状態の判断が必要なため、ユーザー承認なしには実施しなかった。
- ローカルで `bundler-audit` や Rails テストを継続する案: ローカルは実行環境ではなく、Ruby 環境を汚してはいけないというユーザー指示に反するため不採用。既に入った gem は削除した。

## ハマりどころ

- GitHub Actions のログURLを開こうとしたが、Web上では直接ログ本文を取得できなかった。ローカルの `bundle-audit check` と `Gemfile.lock` の差分確認で原因を再現した。
- `bundle-audit check --update` は sandbox 内で `~/.local/share/ruby-advisory-db/.git/FETCH_HEAD` を開けず失敗した。更新なしの `bundle-audit check` ではローカル advisory DB により検出できた。
- `bundle exec rails test` は Spring が `/run/user/1000/spring-1000` を作れず失敗し、`DISABLE_SPRING=1` でも MySQL ソケット `/var/run/mysqld/mysqld.sock` に接続できず失敗した。ローカルテスト不可という前提を `CLAUDE.md` に追記した。
- pi への最初の SSH はタイムアウトしたが、後続の `nc` で port 22 の疎通を確認し、再試行で接続できた。
- pi の `:3000` を最初 sisito と誤認しそうになったが、`ss -ltnp` で owner が `grafana` だと確認した。

## 学び

- このプロジェクトではローカル作業環境を Rails 実行環境として扱ってはいけない。ローカルは編集・git操作・必要最小限のロックファイル更新に限定する。
- pi の `~/sisito` には手動作業の残骸や未コミット bundle update が残っていることがある。反映前に `git status`, `git diff`, `vendor/bundle` の状態を必ず確認する。
- `bin/deploy.sh` は `git pull --ff-only origin master` を実行するため、pi 側に未コミット変更がある状態ではそのまま安全に走らせられない。
- PR #24 のブランチは今回の advisory 修正を含んでいない。PR #24 をマージしただけでは bundler-audit は解消しないため、PR #27 の取り込みが別途必要。
