## 決定事項

- sisimai の更新は Gemfile を触らず `Gemfile.lock` のみ更新する。制約 `~> 5.7` が 5.7.1 を許容するため
- 取り込み経路（system sisimai 5.4.0）とアプリの bundle sisimai は別系統として扱う。Gemfile の bump は取り込みに影響しない
- Claude Code から Pi へはパスフレーズ無しの ed25519 鍵で接続する。非対話実行のためパスワード認証もパスフレーズ付き鍵も使えない
- PR 本文・Issue 本文・コミットメッセージに Claude セッションURLを含めない
- マージ順は #27（脆弱性解消）→ #24 とする。#24 の audit 失敗は master 由来のため

## 捨てた選択肢と理由

- Docker postfix コンテナが取り込み元という仮説: 実際は Pi からの外部送信専用でユーザーに否定された — 手動実行の `update-sisto-db.rb` が実取り込みだと確定した
- 「update-sisto-db.rb は Pi で既に壊れている」という判断: system sisimai が 5.4.0 で互換キーを保持しているため実害は無かった — 将来 5.5.0 以上へ上げた時のリスクとして整理し直した
- `id_rsa` のパスフレーズ解除で SSH を通す案: 当該鍵はそもそもパスフレーズ無しで原因が違った — `ssh-copy-id` で正しい鍵を Pi の authorized_keys に登録して解決した
- Claude Code からのパスワード認証: TTY が無く `ssh-askpass` にフォールバックして失敗する — 鍵認証のみを使う方針にした
- `bundle update --conservative sisimai`（ローカル実行）: ローカル Ruby に gem を入れるため Local Environment Constraints に反する — `bundle lock --update=<gem>` を使う方針に変更し、入った gem は削除した
- マージ済みブランチ `heads/fix_websocket_driver_advisory` 上でのコミット: ブランチ名と内容が乖離する — `heads/update_sisimai_5.7.1` を新規に切って移した
- #24 を audit 赤のまま先にマージする案: 赤の原因は master 由来の loofah / rails-html-sanitizer — #27 を先にマージして green にしてから #24 をマージした

## ハマりどころ

- デプロイ後の起動確認が古い gem 版を報告した → Spring preloader がデプロイ前のプロセスを保持していたため → `spring stop` または `DISABLE_SPRING=1` を付けて再確認し解決した
- 非対話の `rm` が確認プロンプトで停止した → シェルプロファイルで `rm` が `rm -i` にエイリアスされているため → `rm -f` / `command rm` を使って解決した
- Pi で `bin/deploy.sh` の `git pull --ff-only` が止まる状態だった → `Gemfile.lock` にローカル変更が残っていたため → `git stash push` で退避してからデプロイして解決した
- PR #24 の audit が失敗した → master 由来の loofah 2.25.1 / rails-html-sanitizer 1.7.0 の脆弱性のため → #27 をマージ後に `gh pr update-branch 24` で同期して green にした

## 学び

- sisimai 5.4.0 の `Fact#damn` は「Backward compatibility until v5.5.0」コメント付きで `smtpagent`=`decodedby` / `smtpcommand`=`command` を出力する。5.5.0 以降はこの2キーが消える
- Pi の取り込みは system ruby（`/usr/bin/ruby` 3.2.3）で動くため、bundle 側の sisimai を上げても取り込み結果には影響しない
- Claude Code の ssh は TTY を持たないため、パスフレーズ付き鍵もパスワード認証も使えない。自動化用の鍵はパスフレーズ無しである必要がある
- `gh pr update-branch <n>` を使えばローカルのチェックアウト無しに PR ブランチを base と同期できる
- Pi の `vendor/bundle` は `ruby/3.2.0` と `ruby/3.4.0` の両方に gem を持つ。deploy は mise ruby 3.4.9 を使う
